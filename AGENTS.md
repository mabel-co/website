# assurer.ai website — working in this repo

The public assurer.ai site: an Astro static build, no UI framework, no
client-side JS beyond the contact-form script. This repo was migrated as-is
from the `apps/website/` directory of the private development repository;
commands that previously lived in its root Makefile are now targets of the
Makefile here.

## Layout

```
├── src/layouts/BaseLayout.astro  # page shell (head, fonts, meta, favicons)
├── src/pages/                    # one .astro file per route
├── src/components/               # shared markup components (SiteHeader, SiteFooter, …)
├── src/styles/input.css          # Tailwind v4 entry: @source globs, @theme brand tokens, custom CSS
├── scripts/style-class-coverage.py  # CI gate: every referenced class must exist in style.css
├── scripts/capture-evidence.py   # headless-Chromium screenshots at 375/640/1440/1920px
├── public/style.css              # GENERATED by `make style` (Tailwind v4), committed so deploy stays build-time-only
├── public/CNAME                  # www.assurer.ai — GitHub Pages custom-domain pin
├── public/favicon.svg, favicon-dark.svg, og-default.png (1200×630)
├── .github/workflows/deploy-pages.yml  # build + publish to GitHub Pages
└── astro.config.mjs              # site URL and outDir
```

## Commands

Run from the repository root (`make` targets).

| Target | Purpose |
| --- | --- |
| `make install` | npm install (first time only) |
| `make check` | Astro type/content check + class-coverage gate |
| `make style` | regenerate `public/style.css` with Tailwind v4 from `src/styles/input.css` |
| `make style-check` | class-coverage gate only |
| `make build` | production build to `dist/` |
| `make preview` | build, then serve the production output |
| `make clean` | remove `dist/`, `node_modules/`, `.astro/` |

`make check` and `make build` must both pass before you push — the deploy
workflow runs the same two targets.

## Conventions

- Pages go in `src/pages/`; shared `<head>`, fonts and meta belong in
  `BaseLayout.astro`, not in individual pages.
- Styling is Tailwind utility classes compiled by Tailwind **v4** from
  `src/styles/input.css` into the committed `public/style.css` (`make style`).
  The artifact is committed deliberately: deploys copy it and never run the
  Tailwind toolchain, keeping the pipeline compile-time-only (no client JS).
  When you add markup that references a new utility, re-run `make style` and
  commit the regenerated file — `make check` fails if any referenced class is
  missing from the artifact (the #1660 regression gate).
- Brand colors/fonts/radii live in the `@theme` block of
  `src/styles/input.css`; add custom component CSS there too, below the
  `@import`. The class names `heading-underline` and `container-content` are
  project-defined there.
- Fonts (Inter, IBM Plex Mono, Source Serif 4) load from Google Fonts.
- Assets in `public/` were exported from the live site. Keep the favicons and
  `og-default.png` in step with any brand change.
- `dist/`, `node_modules/` and `.astro/` are git-ignored — never commit build
  output. (`public/style.css` is the exception: it is a committed generated
  artifact, not disposable output.)
- Client-side JS lives in `public/js/` as plain JavaScript, referenced with
  `<script is:inline src="…">`. Never put JS logic in inline `<script>` blocks
  — Astro type-checks them as TypeScript.

## Deployment is publication

**Live site: <https://www.assurer.ai>** — this is the `site` value in
`astro.config.mjs`, so it is also the base of every canonical and Open Graph
URL, and it is pinned for Pages in `public/CNAME`.

Any merge to `main` builds and publishes via
[`.github/workflows/deploy-pages.yml`](.github/workflows/deploy-pages.yml)
using the standard GitHub Pages actions. Changes here are public the moment
they merge, so treat copy and imagery as publication and get Owner approval.

**Anonymity (D-041 condition b):** the org and this repo are the public face;
no Owner personal name/handle may appear in content, README, or commit
authorship. Commit through the agent App bots only. The AWS/S3 path in the
private development repository remains the live origin until the Owner flips
DNS; this Pages pipeline goes live for real at cutover.
